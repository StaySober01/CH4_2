# 결정과 미결정 사항

## 현재 협업 방침
- D-008 (2026-10-21): 사용자 요청에 따라 작업 후 빌드·검증은 전부 사용자가 직접 수행한다. 에이전트는 구현과 사용자 실행 절차·예상 결과·로그 안내를 담당한다. 별도 빌드/테스트/PIE/자동 검사/작업 후 검증 명령은 명시적으로 요청받기 전에는 실행하지 않는다. 구현 후 IMPLEMENTED, 사용자 수용 확인 후 해당 범위 VERIFIED로 기록한다. 이전의 에이전트 검증 실행 규칙보다 이 지시를 우선한다.

## 기술 위험
1. 기반 차량/맵과 UMG/차량 모듈 도입 완료. 실제 운전/물리 복제 품질은 수동 검증 필요.
2. UE 버전 차이로 예시 API/템플릿 구조가 달라질 수 있다. 설치 소스로 확인 후 구현한다.
3. OwnerOnly 값은 상대 UI에서 직접 읽을 수 없다. 결과 계산은 서버에서 한다.
4. Listen Host의 OnRep 경로 차이와 UI 중복 생성 가능성: 서버/원격/로컬 역할을 각각 검증한다.
5. 차량 물리 복제·배경 틱 저하는 지터 원인이 될 수 있다. 실제 2창/별도 프로세스 결과로 판단한다.
6. 1Hz 아이템 상태와 즉시 파괴 효과의 누락, 중복 오버랩, 스포너 종료 타이머를 검증한다.
7. 현재 Server Target이 없으므로 Dedicated Server 빌드 가능성을 단정하지 않는다. 기본 수용 환경은 Listen Server다.
8. PlayerStart 3개 구성 완료. 원문의 Starter Content/Scalable와 현재 설정 차이는 남아 있다.


## M02 결정 — 2026-10-21
- D-009: Coins는 int32, BonusMaxSpeed는 float, 초기 값은 각각 0. 초기값은 명세에 없는 구현 가정이다. 서버 setter는 양수 입력만 허용하며 잔액 부족/오버플로/비유한 속도 값을 거부한다. 도전 패널티는 별도 후속 설계.
- D-010: 단위·물리 적용이 필요한 Q-003은 M06에서 확정한다. M02는 단위 없는 추가 값 표시로 제한하여 속도 효과를 구현한 것으로 보고하지 않는다. 이 결정은 물리 정책을 임의로 확정하지 않기 위한 작업 경계다.
- D-011: 기존 차량 WBP를 유지하고 네이티브 UUserWidget 개인 패널을 추가한다. 에셋 생성·컴파일 없이 C++ 변경만으로 표시를 연결할 수 있지만, 시각적 디자이너 편집은 향후 필요 시 WBP로 확장해야 한다.
- D-012: UI 변경 알림은 서버 setter와 OnRep가 공유하며 PC는 초기 스냅샷/PS 재바인딩을 처리한다. 개별 프로퍼티 복제 순서의 일시적 차이는 다음 이벤트에서 반영되며 두 값을 하나의 원자적 거래로 간주하지 않는다.
- D-013: 아이템 미구현 상태의 사용자 검증을 위해 PIE 호스트 한정 Exec 변경 명령을 제공한다. 임의 보상 Server RPC는 추가하지 않는다. 로그 목록은 Client에서 비소유 값이 기본값인지 관찰하는 용도이며 패킷 검사를 대체하지 않는다.

## M03 결정 — 2026-10-21
- D-014: 사용자 지시 “두 플레이어 모두 접속했을 시점부터 5초 대기 후 60초 게임 진행” 적용. GM-006의 첫 플레이어 접속 조건을 2명 접속 조건으로 대체한다. assignment.md 원문은 보존하며 변경된 수용 기준은 m03-match-flow.md에 기록한다.
- D-015: 사용자 선택으로 대기 중 2명 미만이면 취소, 다시 2명이 모이면 5초 재시작. 질문에서 제시한 경기 중 이탈 정책은 타이머 계속 진행으로 적용한다.
- D-016: 서버에서 PostLogin을 마친 비관전자 PC를 연결 참가자로 집계한다. 최소 2명 이상이면 시작하며 세 번째 접속을 자동 거부하지 않는다. 후입장은 현재 상태 수신, 종료 후 자동 재시작 없음. 별도 재접속 데이터 보존은 추가하지 않는다.
- D-017: 단계/시간/인원/카운트다운 여부를 단일 복제 구조체로 전달하고 공통 변경 이벤트 사용. 서버 월드 타이머가 1초마다 감소하며 벽시계 기반 타이머/클라이언트 보간은 도입하지 않는다. 서버 일시정지·심한 지연에 따른 실제 벽시계 차이는 있을 수 있다.
- D-018: 기존 개인 패널에 공용 경기 행을 추가. PC는 World GameStateSetEvent로 늦은 GameState 도착을 처리한다. 승자/행동 제한은 후속 마일스톤이다.

## M04 결정 — 2026-10-21
- D-019: 사용자 요청 “UI는 WBP로 하자” 적용. 기존 개인/경기 패널도 WBP_PlayerStats로 전환하며 새로운 WBP_Chat과 함께 Designer 편집을 지원한다. 기존 네이티브 패널 생성 결정(D-011)은 이 지시로 대체한다.
- D-020: 사용자 선택으로 최대 200 UTF-16 코드 단위(FString.Len), 최소 0.5초 전송 간격. 서버 단조 시간 기준으로 검사하여 게임 시간 정지와 별개로 적용. 클라이언트 검사 외에 서버에서도 재검사한다.
- D-021: PC 소유 Server RPC→각 PC Client RPC 경로. 로컬 선표시 없음. 서버 PS에서 발신자 이름을 취하고 제어문자를 한 줄 공백으로 정리한다. 상태 동기화를 위한 Multicast는 추가하지 않는다.
- D-022: 채팅은 모든 경기 상태에 허용, 최근 50건을 로컬 UI 메모리 제한으로 보관. 후입장 과거 기록/영구 저장 미지원. 입력 중 UIOnly/입력 중립화, Enter 제출·Escape 및 포커스 이탈 취소 후 GameOnly 복귀.
- D-023: 사용자 빌드 정책 때문에 새 부모 클래스를 로드해야 하는 WBP 생성은 빌드 후 사용자 실행 스크립트로 제공한다. 기존 동명 에셋의 배치는 덮어쓰지 않는다. 생성 전에는 CHAT-002 등을 완료 처리하지 않는다.
