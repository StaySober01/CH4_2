# 결정과 미결정 사항

## 단계 1 작업 경계 (이력)
- D-001: 이번 단계는 문서만 작성. 게임 코드·설정·에셋 변경 없음. 사용자의 단계별 진행 요청이 근거다.
- D-002: 기존 docs/assignment.md가 없어 사용자 제공 과제 첨부를 원문 그대로 보존. 누락 내용을 추측하지 않는다. 이미지와 CX.zip 본체는 첨부되지 않아 분석할 수 없다.
- D-003: 현 프로젝트명 CH4_2와 연결 엔진 5.6을 분석 기준으로 사용. 이는 과제의 5.5.4/CX 요구를 대체하기로 확정한 결정이 아니다.
- D-004: GameMode 서버 판정, GameState 공용 상태, PlayerState OwnerOnly 개인 상태를 계획. 전체 코인 공개보다 과제 조건에 맞지만 승자는 서버에서 별도 산출해야 한다.

## 단계 2a 결정
- D-005: 사용자 Vehicle 템플릿 사용 승인. CH4_2/UE5.6에 설치된 TP_VehicleAdv 도입. 공식 공유 Vehicles/Input 포함. C++ variants는 에셋 부모 의존성 보존을 위해 함께 가져왔다.
- D-006: Blueprint 참조는 CoreRedirects로 연결하고 바이너리는 엔진 API로만 변경한다.
- D-007: 과제 예시 Start 검사 크기/offset 사용. 3개 Start를 500cm 간격으로 배치. 공간이 없으면 checkf 대신 경고 후 스폰 실패 반환. 배치 간격은 과제 수치가 아닌 이번 맵 구성값이다.
- Q-001 해결: 기존 CH4_2/UE5.6 유지 및 Vehicle 도입. Scalable 전환/Starter Content 추가는 수행하지 않았으며 별도 편차로 추적한다.

## 기술 위험
1. 기반 차량/맵과 UMG/차량 모듈 도입 완료. 실제 운전/물리 복제 품질은 수동 검증 필요.
2. UE 버전 차이로 예시 API/템플릿 구조가 달라질 수 있다. 설치 소스로 확인 후 구현한다.
3. OwnerOnly 값은 상대 UI에서 직접 읽을 수 없다. 결과 계산은 서버에서 한다.
4. Listen Host의 OnRep 경로 차이와 UI 중복 생성 가능성: 서버/원격/로컬 역할을 각각 검증한다.
5. 차량 물리 복제·배경 틱 저하는 지터 원인이 될 수 있다. 실제 2창/별도 프로세스 결과로 판단한다.
6. 1Hz 아이템 상태와 즉시 파괴 효과의 누락, 중복 오버랩, 스포너 종료 타이머를 검증한다.
7. 현재 Server Target이 없으므로 Dedicated Server 빌드 가능성을 단정하지 않는다. 기본 수용 환경은 Listen Server다.
8. PlayerStart 3개 구성 완료. 원문의 Starter Content/Scalable와 현재 설정 차이는 남아 있다.
